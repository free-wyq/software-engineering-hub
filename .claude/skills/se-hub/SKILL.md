# 软件工程技能中心 (se-hub)

本 skill 是**路由入口**,不直接产出内容。职责:判断当前请求处于软件工程哪个阶段,加载对应垂直技能,把执行交给它。

## 路由表

| 阶段 | 关键词信号 | 加载 |
|---|---|---|
| 需求 | 撰写需求文档/PRD/用户故事/验收标准、梳理/拆解需求 | `references/requirement/SKILL.md` |
| 设计 | 架构/方案/技术选型、接口设计/数据模型设计 | `references/design/SKILL.md` |
| 编码 | 系统化重构、编码规范落地(前端/后端/DevOps/重构/code-review) | `references/coding/SKILL.md`(再下分一层) |
| 测试 | 测试策略/用例设计、单元/集成/e2e/边界/覆盖率规划 | `references/testing/SKILL.md` |
| 交付 | 部署/发布/上线流程、运维/CI/CD/监控/回滚规划 | `references/delivery/SKILL.md` |

## 路由规则

1. **先确认是不是"方法论级"任务**:日常改 bug、写小函数、加几行代码——直接用通用编程能力回答,**不必走 hub**。只有需要工程化规范输出(文档/方案/策略/流程)时才进路由。
2. **看用户当前在做什么**:正在改的文件、当前仓库技术栈、对话上文,往往直接暴露阶段(在 `*.test.*` 里规划用例 → 测试;在改 `Dockerfile` 做部署 → 交付)。
3. **没有上下文时看关键词**:按上表信号匹配。编码类请求先进 `coding` 子 hub,由它再下分前端/后端/devops/重构/code-review。
4. **跨阶段请求**:一次请求涉及多阶段(如"设计接口并写单测")→ 按主阶段路由,子技能里再处理次阶段;不要一次加载多个子 skill。
5. **匹配不上**:落空时不要硬分派,直接用通用工程能力回答,并提示用户可补充垂直技能。

## 执行动作

判定阶段后:

```
Read 对应 references/<stage>/SKILL.md
按该子 SKILL.md 的指令执行后续工作
```

子 SKILL.md 才是真正的方法论载体。本 hub 不重复其内容。

## 边界

- hub **不干活**:不写代码、不写文档、不写测试。只判断 + 分派。
- 子 SKILL.md 内容**不内联进 hub**:渐进披露,用到才 Read,避免一次性把全部阶段内容灌进上下文。
- 日常编程**不强路由**:hub 是窄触发,简单任务不过 hub,避免变噪音中间件。
